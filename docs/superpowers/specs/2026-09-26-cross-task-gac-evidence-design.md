# 跨任务与 GAC 证据扩展实验设计

日期：2026-09-26
状态：待书面确认
适用项目：Direction–Speed（DS）动作空间分解的机器人强化学习实验

## 1. 背景与目标

现有 task1 固定温度确认实验表明，扰动匹配的 tangent DS 在归一化回报 AUC 上优于 Cartesian + L2 projection：4 个确认种子的配对均值差为 `+0.02069`，中位数为 `+0.02556`，4 个种子中 3 个为正；加上两个 pilot 种子后，6 个种子的操纵检查均通过。与此同时，确认实验的 success AUC 和最终成功率没有改善，说明当前证据支持“提高密集回报下的学习效率”，但还不足以支持“提高任务成功率”或“跨任务普遍有效”。

本设计的目标是补齐三类证据：

1. 在 task2 和 task3 上检验扰动匹配结论能否跨任务复现；
2. 加入公开的 Geometric Actor-Critic（GAC）强基线，并显式区分论文公式与公开代码行为；
3. 同时报告归一化回报和成功率，防止只选择有利指标、任务或种子。

本阶段不以“某个方法必须胜出”为验收条件。无论结果正负，只要协议得到执行、原始日志完整且统计口径未改变，就构成有效实验。

## 2. 研究问题与预注册声明

### RQ1：跨任务几何效应

在 Cartesian 探索扰动的状态内平移半径标准差与平均角偏差被匹配后，DS tangent 探索是否仍能提高归一化回报 AUC？

### RQ2：与 GAC 的竞争力

DS 方法相对于 GAC 的公开代码版本、论文公式版本以及面向机器人动作语义的分组版本，是否具有更好的样本效率或成功率？

### RQ3：GAC 论文—代码差异

GAC 论文中的最终方向归一化与公开代码中缺少该归一化的行为，是否会显著改变动作范数、探索几何和性能？

### RQ4：密集回报与成功率是否一致

若归一化回报 AUC 提升但 success AUC 不提升，应将其解释为“密集回报学习更快”，而不是“任务完成能力更强”。两者方向不一致时必须在摘要、正文和结论中同时披露。

### 预注册声明

- task2 和 task3 的所有正式种子均必须纳入汇总，不因失败、极端值或不符合假设而删除；只有进程崩溃、日志损坏或环境不可用可重跑，并保留故障记录。
- 校准阶段不得读取评估回报或成功率，只能读取动作几何统计。
- task2 的结果不得用于决定是否运行 task3；task3 是预先承诺的困难压力测试。
- GAC 的工程冒烟结果不得进入正式统计，正式种子不得用于调参。
- task4 暂不纳入本轮，因为当前工作区没有可核验的 task4 原始日志来确定合理预算。这是范围限制，不是根据结果筛选任务。

## 3. 方法与命名

### 3.1 共同训练骨架

除“忠实复现外部算法”所必需的差异外，各方法共用：

- 相同的离线数据、在线采样日程和 replay buffer；
- 相同的 critic 架构、目标网络更新、batch size、优化器和评估代码；
- 相同的观测编码器与随机种子约定；
- 相同的环境动作上下界与 episode 终止规则；
- 固定温度 `alpha = 0.1` 的本项目共同学习器。

正式运行前，程序必须输出编译后的完整配置、git commit、脏工作区标识、设备信息和环境版本。

### 3.2 Cartesian + L2 projection

策略先在 Cartesian 坐标中生成平移动作，再将平移向量投影到允许的 L2 球内。它是跨任务几何校准的参考分布，也是主要对照方法。

### 3.3 DS tangent（默认）

平移动作被写成

\[
\mathbf a_{xyz}=s\mathbf d,
\]

其中 `d` 是单位方向，`s` 是非负速度。方向噪声位于单位球面的切空间，速度和 yaw/gripper 等标量头独立建模。默认版使用当前固定超参数，不读取 Cartesian 的几何目标。

### 3.4 DS tangent（扰动匹配）

结构与默认 tangent 相同，但通过 reward-blind 控制器选择方向和速度噪声尺度，使其径向矩和角向矩接近 Cartesian + L2 projection。匹配只约束探索扰动，不匹配网络容量、表示或最终回报。

### 3.5 GAC-code

这是“外部算法忠实复现”，使用 GAC 公开实现的实际语义：

复现源固定为公开仓库 `Lin-Zhihao98/GAC` 的 commit `374ae2c9ef284a6ef715a67c1fdce864ebad6f44`。源代码快照、许可证和本地移植差异必须随实验配置归档；上游后续变化不自动进入本实验。

\[
\mathbf a=r\,[w(\kappa)\boldsymbol\mu+(1-w(\kappa))\boldsymbol\xi],
\]

其中公开代码使用 `w = sigmoid(0.5 * kappa)`，且混合后不做最终 L2 归一化。`kappa` 采用公开实现中的软限制、初始化、正则项、actor 目标和 target-Q 熵项；温度固定为公开实现的 `alpha = 1`。为满足本机器人环境的合法动作域，半径预先固定为 `r = 1.0`，不使用论文在其他任务上的 `2.5`。该方法作用于完整动作向量，因此属于外部竞争基线，不属于只改变 XYZ 参数化的因果消融。

### 3.6 GAC-paper

该版本严格实现论文动作方程：

\[
\mathbf a=r\,\mathrm{normalize}\left(
\sigma(\kappa)\boldsymbol\mu +
(1-\sigma(\kappa))\boldsymbol\xi
\right).
\]

它使用 `w = sigmoid(kappa)`，并在混合后做最终 L2 归一化。除这两个论文—代码差异外，优化目标、正则项和 `alpha = 1` 与 GAC-code 相同，`r = 1.0`。两版本的差值用于回答 RQ3，不把其中表现更好的版本事后改名为“GAC”。

### 3.7 GAC-DS

GAC-DS 是面向机器人动作语义的分组强基线：只对 XYZ 方向使用 GAC 的球面混合；速度 `s`、yaw 和 gripper 由独立的有界概率头产生。最终平移仍为 `a_xyz = s d`。这避免强迫速度、旋转和夹爪共享一个完整动作球面。

GAC-DS 使用本项目共同学习器和 `alpha = 0.1`。若 `log p_rest` 表示速度、yaw 和 gripper 头的联合对数概率，则 actor 目标固定为

\[
L_\pi=\mathbb E[\alpha\kappa_{xyz}+\alpha\log p_{rest}-Q(s,a)],
\]

target-Q 的熵项固定为

\[
Q_{target}=r+\gamma(1-d)\left[
\min_i Q_i'(s',a')-\alpha\kappa_{xyz}-\alpha\log p_{rest}
\right].
\]

这里 `kappa_xyz` 延续 GAC 将方向熵近似为 `-kappa` 的约定，其余动作维度使用标准随机策略熵。GAC 公开代码中的 kappa 范围、初始化和 kappa 正则项也原样用于 `kappa_xyz`，其系数由上述固定 commit 决定；其余 DS 正则保持不变，重复约束不得叠加。该公式在实现前必须有代数级单元测试，且不得根据正式回报调整符号或权重。GAC-DS 是结构性强基线，不是对 GAC 官方结果的忠实复现。

本规格经书面批准后，取代 `docs/gac_baseline_protocol.md` 中尚未执行的 seed-996 和“两种子 GAC pilot”阶段；旧文件继续作为方法动机与历史记录保留，不再作为运行清单。

## 4. 跨任务校准与正式实验

### 4.1 通用几何统计

每个检查点从固定的 512 个状态构成面板，每个状态采样 32 个动作。面板在同一任务内对所有方法保持一致。相对策略中心动作的平移扰动 `delta_xyz` 计算：

- 径向一阶矩：`E[||delta_xyz||_2]`；
- 状态内平移半径标准差；
- 径向二阶矩：`E[||delta_xyz||_2^2]`；
- 角向扩散：扰动方向与中心方向的平均夹角；
- 方向覆盖：单位球面分箱占用率；
- 速度均值、标准差及上下界饱和率；
- yaw/gripper 的均值、标准差及饱和率。

控制器沿用 task1 已验证的操纵定义：匹配状态内平移半径标准差和平均夹角。半径均值与二阶矩只报告、不控制，因为 task1 的全矩匹配工程实验曾导致策略通过移动状态相关速度中心来补偿控制器。其余统计用于诊断，不能在看到正式回报后升级为新的匹配目标。

### 4.2 task2 校准

1. 运行 Cartesian + L2 projection 的两个校准种子 `984, 985`，每个 `500k` 环境步，检查点间隔 `50k`；关闭回报与成功率评估。
2. Cartesian 匹配目标取两个种子在 `400k` 和 `500k` 四个观测点的半径标准差与平均角偏差均值；其余几何量只作为诊断。使用末端两个检查点而非单点，以降低随机波动。
3. 使用独立工程种子 `993` 运行匹配控制器至 `100k`。回报与成功率评估关闭，控制器持续记录纯几何更新；额外归档 `80k` 和 `100k` 状态面板。
4. 工程门槛：最后五次控制器更新的半径标准差绝对误差均不超过 `0.02`，平均夹角绝对误差均不超过 `0.05 rad`；最后一个检查点也必须同时通过。若门槛失败，只允许修复控制器或扩大可达参数域；不得读取回报。
5. 固定控制器和所有配置后，运行正式种子 `80–85`，每个 `500k` 步。

task2 正式条件为：

- Cartesian + L2 projection；
- 默认 DS tangent；
- 扰动匹配 DS tangent。

每 `50k` 步评估一次，每次 50 个 episode；训练初始点也记录，以便 AUC 使用同一横轴。

正式 matched seed 的操纵门槛为：10 个非零检查点中至少 8 个同时满足上述两个误差容限。最终检查点还必须满足表示容量门槛：方向中心在固定状态面板上的标准差均值大于 `0.05`，raw-speed 中心标准差大于 `0.01`，yaw 和 gripper 两个标量中心的标准差各大于 `0.01`。这些门槛只决定因果解释是否成立，不决定是否保留性能结果。

### 4.3 task3 校准与压力测试

task3 使用完全独立的几何目标，不能复用 task2 的匹配参数。

1. Cartesian 校准种子为 `986, 987`，每个 `1M` 步，关闭回报与成功率评估。
2. 匹配目标取两个种子在 `800k` 和 `1M` 四个观测点的半径标准差与平均角偏差均值，其余几何量只作为诊断。
3. 独立工程种子 `994` 运行至 `200k`。回报与成功率评估关闭，控制器持续记录纯几何更新；额外归档 `160k` 和 `200k` 状态面板，并使用与 task2 相同的工程门槛。
4. 固定后运行正式种子 `86–91`，每个 `1M` 步。

正式条件与 task2 相同。每 `100k` 步评估 50 个 episode，并记录训练初始点。task3 即使全部方法接近零成功率，也作为预注册的 floor/stress-test 结果完整报告，不更换任务。

task3 正式 matched seed 同样要求 10 个非零检查点中至少 8 个通过半径标准差与角偏差门槛，并通过与 task2 相同的最终表示容量门槛。

## 5. GAC 实验阶段

### 5.1 实现验证

任何性能运行前必须通过以下测试：

- GAC-code 的动作范数不超过 `r`，且能够通过构造样例复现“混合后不归一化”；
- GAC-paper 的动作范数在数值误差内等于 `r`；
- `kappa -> +inf` 时动作趋近均值方向，`kappa -> -inf` 时趋近噪声方向；
- GAC-code 与 GAC-paper 在固定输入上的差异与公式一致；
- GAC-DS 的 XYZ、速度、yaw、gripper 均满足环境边界；
- GAC-DS actor 和 target-Q 的熵项符号有解析构造测试；
- 所有新分布可反向传播，极端 `kappa` 下无 NaN/Inf；
- checkpoint 保存—恢复后，同一输入和随机键产生一致输出；
- 现有完整测试套件无回归。

随后只用工程种子 `992` 在 task1 运行 `50k` 步，评估关闭。工程运行仅检查吞吐、显存、数值稳定性、动作边界和日志完整性。

### 5.2 task1 正式竞争实验

正式条件为：

- Cartesian + L2 projection；
- 扰动匹配 DS tangent；
- GAC-code；
- GAC-paper；
- GAC-DS。

使用全新种子 `92–97`，每个 `300k` 步；每 `50k` 步评估 50 个 episode。所有条件从同一份离线数据和相同在线采样预算开始。旧 task1 结果只能作为历史证据，不与这些新种子混合计算显著性。

GAC-code 和 GAC-paper 因学习目标、温度与完整动作支持不同，只进入“算法竞争”表。Cartesian、匹配 DS 和 GAC-DS 进入“共同机器人训练骨架”表。论文中不得把 GAC-code/GAC-paper 的差异解释为纯参数化因果效应。

## 6. 指标与统计分析

### 6.1 预先固定的指标

主指标：归一化回报 AUC，先对横轴除以最大环境步数，再用梯形积分，因此数值是 `[0,1]` 训练进程上的平均归一化回报。

关键次指标：

- success AUC；
- 最终检查点成功率；
- 最终检查点归一化回报；
- 达到预设成功率阈值所需环境步数；若未达到则记为删失，不记为最大步数；
- 每千步墙钟时间、峰值显存和采样吞吐。

每个任务均显示完整学习曲线、种子散点和配对差值，阴影必须注明是标准差、标准误还是置信区间。

### 6.2 推断方法

- 同一正式 seed 编号在各条件间配对。
- 对方法差值报告均值、中位数、6 个逐种子差值、95% 配对 bootstrap 置信区间和 improvement probability。
- task2/task3 的跨任务汇总使用“先任务内归一化、再按任务等权”的分层 bootstrap，不能按 episode 数或训练步数给 task3 更高权重。
- task1 GAC 比较对 5 个方法的主指标使用 Holm 校正；同时保留未校正效应量和置信区间。
- 不将 `p < 0.05` 作为唯一结论门槛。核心结论依据效应量、置信区间、跨任务方向一致性和成功率指标共同表述。

### 6.3 允许的结论边界

- 只有归一化回报 AUC 改善：写“提高密集回报样本效率”。
- success AUC 与最终成功率也改善：才可写“提高任务完成效率”。
- task2 改善但 task3 floor：写“在可学习任务上复现，在困难任务上未形成可判别证据”。
- 匹配操纵未通过：性能比较只能作为观察性结果，不能作为“几何匹配后的因果证据”。
- GAC-DS 优于 GAC-code：只能说明语义分组在本机器人设置更适合，不能声称推翻 GAC。

## 7. 失败处理与停止规则

- **进程或日志故障**：用相同 seed 和配置重跑，保存原故障目录与说明。
- **数值故障**：若工程种子出现 NaN、越界或 checkpoint 不一致，先修实现并重新通过测试；不得直接进入正式运行。
- **几何不可达**：若控制器已到参数边界仍无法匹配，记录 capacity failure，停止该任务的“匹配因果”运行，但仍可运行默认 DS 与 Cartesian 作为描述性基准。
- **正式操纵失败**：所有性能结果照常报告，但降级因果解释；不得依据回报重新校准。
- **任务 floor**：完成预定预算并报告，不临时追加步数。任何更长预算必须作为新的、单独预注册实验。
- **资源中断**：允许从已验证 checkpoint 恢复；恢复次数和缺失区间写入元数据。

## 8. 产物与可追溯性

每个运行目录至少包含：

- 原始训练、在线采样、评估和几何统计日志；
- 用户配置与程序展开后的最终配置；
- seed、run group、任务名、方法名、git commit 和环境版本；
- checkpoint 及其步数；
- 分析脚本生成的 per-seed CSV、summary CSV、decision JSON 和图；
- 若有失败或恢复，包含 machine-readable incident 记录。

分析程序只能从原始日志生成汇总，不允许手工填写正式结果。图表中的每个汇总点必须能够回溯到 seed 和 checkpoint。

## 9. 执行顺序与资源预算

硬件按两张 RTX 6000 Ada 规划，每张卡最多同时运行 6 个已验证不会 OOM 的进程。顺序如下：

1. 实现并测试 task-agnostic 校准器和三种 GAC 版本；
2. task2 Cartesian 校准与 reward-blind 匹配工程验证；
3. task2 三方法、六种子的正式 `500k` 实验；
4. task1 五方法、六种子的 GAC 正式 `300k` 实验；
5. task3 Cartesian 校准与匹配工程验证；
6. task3 三方法、六种子的正式 `1M` 压力测试；
7. 冻结原始结果，统一统计分析并更新论文。

不同阶段可以在实现无依赖时并行使用 GPU，但校准必须先于对应任务的正式 matched 运行。run-group 名保持简短，避免已知的文件名长度问题。

## 10. 验收条件

本设计完成的判据不是“DS 显著获胜”，而是：

1. 新增单元测试和现有完整测试套件全部通过；
2. task2/task3 校准均有独立 seed、固定状态面板和 reward-blind 证据；
3. 所有预注册正式条件与 seed 完成，或有可审计的基础设施故障记录；
4. 操纵、容量和数值稳定性检查均有机器可读结论；
5. 主指标与所有关键次指标同时报告，无任务、seed 或指标选择；
6. 论文准确区分 GAC-code、GAC-paper、GAC-DS 以及因果消融与算法竞争；
7. 论文声明 task4 缺失及本轮结论的任务范围。

书面规格确认后，下一步是把本设计拆成逐文件、逐测试、逐命令的实现计划；在实现计划再次确认之前，不启动新实验。
